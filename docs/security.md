# セキュリティ・OAuth・監査ログ

## 1. ファイルアクセス

* ファイル操作は `--allow-dir` の中に限られ、`..` やシンボリックリンクで外に出ることはできません。`--allow-read-dir` で指定したディレクトリは、読み取り専用ツール（`read_file`・`list_dir`・`search_files`・git）からだけ参照できます（書き込み・削除・コマンドの `cwd` は不可）。
  * 例外として `ask` では、`read_file` / `list_dir` / `search_files` に限り、ユーザーが承認すれば外も読めます。承認の問い合わせに対応していないクライアント（Gemini アプリなど）では読めません。読み取りのツールにはクライアント側の確認が出ないためです。`--deny-glob` は外でも効きます。
* `--deny-glob` はシンボリックリンクのリンク先にも適用されます。
* Windows では UNC パス・ドライブ相対パス・代替データストリーム（`:`）を拒否します。
* `--deny-glob` が守るのはファイル操作ツールだけです。コマンドはプロセスの権限で読めるファイルをすべて読めます。

## 2. モードと承認

* `read` では、中継先 MCP サーバーのツールのうち、そのサーバーが読み取り専用の印を付けたものだけを呼べます。`--mcp-server` で登録したサーバーでも同じです。
* `ask` では、ファイルの変更・許可ディレクトリの外の読み取り・コマンドの実行・端末（`tty`）への入力・中継先 MCP サーバーの起動と停止・読み取り専用でない中継先ツールの呼び出しに、毎回ユーザーの承認が要ります。承認したシェルに後から別のコマンドを打ち込めないよう、`write_stdin` の入力も1回ずつ確認します。
  * クライアントが承認の問い合わせ（MCP の elicitation）に対応していれば、sh-mcp が実行内容（パス・diff・コマンドライン）を示して確認します。承認されなければ実行しません。
  * 対応していないクライアントでは、クライアント自身の確認画面に任せます。sh-mcp からは強制できません。Gemini アプリは操作ごとに許可カードを出しますが、「常に許可」を選ぶと以後は確認が出なくなります。
  * 接続中のクライアントでどちらになるかは `get_environment` に表示されます。
* `--auto-approve-command` のプログラムは `ask` でも承認なしで実行されます。起動時に絶対パスへ解決し、後から `PATH` で差し替えられないようにします。
  * 制限するのはプログラムだけで、引数は制限しません。引数次第で任意のコードを実行できるプログラムは指定しないでください。
  * 例: `git`（`-c core.pager=…` や `--upload-pack` で任意コマンドを実行でき、ファイルも変更できる）、`docker`（実質 root）、シェル、インタプリタ、`find`、`xargs`、`env`、`make`、`go`、`npm`
  * 向いているのは `df`, `free`, `uptime`, `journalctl` のような参照系のプログラムです。
* git は `--auto-approve-command` ではなく `git_status` / `git_diff` / `git_log` を使ってください。リポジトリの設定によるプログラムの実行・リポジトリへの書き込み・ネットワーク接続を止めて実行するので、全モードで承認なしに使えます。
  * ただし `.git/config` で定義した clean フィルタは止められません。`ask` で `.git/` の中への書き込みを承認するときは注意してください。
* `full` では、sh-mcp を動かしているユーザーができることは何でもできます。被害の範囲を限りたい場合は、コンテナや VM、systemd のサンドボックスなど、OS 側で sh-mcp を閉じ込めてください。sh-mcp が決めるのはモードと各ツールの動作だけで、OS 側の隔離は利用者の環境に任せます。
* タイムアウト・`kill_job`・終了時は子プロセスも含めてまとめて終了します。ただし Unix の対話シェル（`tty`）が `&` でバックグラウンドに回したプロセスは対象外です（多くは端末が閉じたときの `SIGHUP` で終了します）。

## 3. HTTP

* HTTP では 16 文字以上の認証トークンが必須です。
* `--public-url` を指定すると、そのホスト名とループバック以外の `Host` ヘッダーを拒否します。
* ブラウザからのクロスオリジンのリクエストは拒否します。

## 4. OAuth

`--public-url` と認証トークンを設定すると、OAuth 2.1 の認可サーバーが有効になります。クライアントは動的に登録され（DCR）、同意画面で `SH_MCP_AUTH_TOKEN` を入力すると接続が許可されます。

使うパスは `/.well-known/*` と `/oauth/*` です。PKCE は必須で、同意画面でのトークンの入力ミスは 1 分に 5 回までです。

* トークン類は `SH_MCP_AUTH_TOKEN` から作った鍵で署名し、サーバーには保存しません。再起動後もそのまま使えます。
* アクセストークンは 1 時間有効です。リフレッシュトークンは期限がなく、更新しても変わりません（Gemini との互換のため）。
* `/oauth/revoke` による失効は再起動すると消えます。確実に失効させるには `SH_MCP_AUTH_TOKEN` を差し替えて再起動します（全トークンが無効になります）。
* OAuth を有効にしても、`Authorization: Bearer <SH_MCP_AUTH_TOKEN>` で直接接続できます。

## 5. 監査ログ

全ツール呼び出しを JSONL で記録します（`--audit-log` 未指定時は stderr）。

```json
{"time":"2026-11-25T09:00:00Z","level":"INFO","msg":"tool_call","event":"tool_call","tool":"write_file","args_summary":{"bytes":128,"path":"main.go","sha256":"a1b2c3d4e5f60708"},"duration_ms":2,"ok":true,"client":"oauth:Gemini#1234abcd"}
```

* ファイル本文、`call_mcp_tool` の引数の値と中継先のエラー内容、`write_stdin` の入力（パスワードかもしれないため）は記録しません（サイズ・ハッシュ・キー名のみ）。
* `run_command` の引数と `run_shell` のスクリプトの先頭（200 文字）は記録します。秘密情報はコマンドラインに書かず、`--env-passthrough` で渡してください。
* ログファイルは `0600` で作成し、`SIGHUP` で開き直します。
